# Ребрендінг: перемикач старого/нового дизайну

Дата: 2026-08-25
Гілка: `redesign/rebrand-2026`

## Контекст

Компанія провела ребрендінг: змінилися фірмові кольори, лого та графічна
мова (контурні намальовані від руки квіти як акцент, а не домінанта).
Джерела:

- `/Users/vladbilobrov/Downloads/new_logo.jpeg` — нове лого: коло
  кольору `#9EAF00` (оливково-салатовий) з написом "KVITKOVA." (жирний
  гротеск) + "POVNYA" (тонкий шрифт), текст кольору `#FAF8E9`.
- `/Users/vladbilobrov/Downloads/Новий брендінг.pdf` — презентація
  фірмового стилю (агенція Kukurudza), 9 слайдів. Ключові принципи:
  - Акцентні кольори ротуються за темою/сезоном (оливковий, жовтий,
    теракотовий, бордовий, рожевий), але не є єдиною фіксованою
    палітрою — це набір для соцмереж-контенту.
  - Контурна квіткова графіка, намальована від руки — головна
    "родзинка" бренду, використовується як **невеликий акцент**, фокус
    залишається на фото.
  - Фотостиль: натуральний lifestyle/editorial, живі букети, текстури
    паперу, легкий рух/блюр в окремих візуалах.
  - Типографіка: контраст масивного гротеска та тонкого сучасного
    шрифту.
  - Презентовано 3 варіанти виконання (Сміливий/Обережний/Балансовий) —
    відрізняються інтенсивністю кольору, структура однакова. Для сайту
    обрано **Балансовий**.

Замовник хоче, щоб новий дизайн можна було увімкнути/вимкнути в
адмін-панелі (Payload), без видалення старого дизайну.

## Рішення (підтверджено користувачем)

- Варіант виконання: **Балансовий**.
- Механізм перемикання: **глобальний тумблер** в Payload globals
  "Налаштування сайту" (`site-settings`) — одна властивість вмикає
  новий дизайн для всіх відвідувачів одразу.
- Глибина редизайну: **візуальна тема (кольори/шрифти/лого/декоративна
  графіка) + оновлені ключові компоненти** (Hero, Logo, ProductCard),
  без перекомпонування layout сторінок.

## Архітектура

### 1. Payload-поле

У `src/globals/SiteSettings.ts` додається select-поле:

```ts
{
  name: 'designTheme',
  type: 'select',
  label: 'Дизайн сайту',
  defaultValue: 'old',
  options: [
    { label: 'Старий дизайн', value: 'old' },
    { label: 'Новий дизайн (ребрендінг)', value: 'new' },
  ],
  admin: {
    position: 'sidebar',
    description: 'Перемикає весь сайт між старою та новою фірмовою темою',
  },
}
```

### 2. Прокидання теми в розмітку

`src/app/(storefront)/layout.tsx` вже завантажує `site-settings` global.
Значення `siteSettings.designTheme` виставляється як атрибут
`data-theme` на кореневому `<html>`:

```tsx
<html lang="uk" data-theme={siteSettings.designTheme} className={...}>
```

Жодних React Context/клієнтських провайдерів не потрібно — все інше
керується CSS-каскадом від цього атрибута. Це узгоджується з тим, як
проєкт уже влаштований (кожна сторінка сама тягне `site-settings` через
Payload,ніякого глобального theme-стану в JS немає).

### 3. CSS-токени (основний обсяг редизайну)

У `src/app/(storefront)/globals.css` існуючі `:root` змінні
(`--color-cream`, `--color-blush`, `--color-sage`, `--color-ink`,
`--color-ink-soft`, `--color-accent`) залишаються дефолтом (=старий
дизайн). Додається блок:

```css
:root[data-theme='new'] {
  --color-cream: #faf8e9;
  --color-blush: #f3f1ea;
  --color-sage: #c9d170;
  --color-ink: #2b2b28;
  --color-ink-soft: #6d6a60;
  --color-accent: #9eaf00;
  --color-accent-warm: #e8871e; /* новий, другорядний акцент */
}
```

(`--color-accent-warm` додається як нова змінна в обох темах — у
старій темі отримує близький до `--color-accent` відтінок, щоб
компоненти, які на неї спираються, не ламались, якщо тему вимкнено.)

Оскільки всі існуючі компоненти вже стилізовані через ці Tailwind
токени (`bg-cream`, `text-ink`, `text-accent`, `bg-blush`, тощо), зміна
токенів автоматично перефарбовує Header, Footer, PricingCard/Grid,
FaqAccordion, CartDrawer, TestimonialsGrid, WeddingPromo, TickerStrip,
FormatsGrid, форми (`.input`), кнопки — **без правок їхнього коду**.

Вага шрифту: контраст "жирний гротеск / тонкий сучасний" з брендбуку
реалізується наявним Montserrat (уже підключений), вагами 900 і 300,
без нового вебфонту:

```css
:root[data-theme='new'] {
  --font-weight-brand-bold: 900;
  --font-weight-brand-light: 300;
}
```

використовується точково в Logo/Hero (нижче), без переписування
загальної типографіки сайту.

### 4. Компоненти з окремою розміткою для нової теми

Три компоненти отримують дубльовану розмітку, що перемикається чистим
CSS (`[data-theme='new'] .theme-new { display: … }` /
`[data-theme='new'] .theme-old { display: none }` — реалізується
Tailwind-класами `hidden [html[data-theme='new']_&]:flex` тощо, без
JS-розгалужень і без гідратаційних розбіжностей):

1. **`Logo`** (`src/components/storefront/Logo.tsx`) — стара версія
   (місяць-мітка + "KVITKOVA"/"POVNYA" з тонким розділювачем)
   залишається як є. Додається нова версія: оливкове коло-бейдж (SVG,
   `fill="var(--color-accent)"`) з написом "KVITKOVA." (bold) +
   "POVNYA" (light) кремовим кольором усередині кола — повторює лого з
   `new_logo.jpeg`. Обидві версії рендеряться в DOM, видимість
   перемикається CSS-селектором за `data-theme`.
   Примітка: якщо власник завантажить растровий файл лого через
   існуюче поле `site-settings.logo`, воно, як і зараз, матиме
   пріоритет над обома SVG-варіантами (логіка в `Header.tsx` не
   змінюється).

2. **`Hero`** (`src/components/storefront/Hero.tsx`) — додається
   контурний SVG-акцент квітки/гілки (у стилі брендбуку) в куті
   банера, видимий лише в новій темі; заголовок отримує вагу 900,
   підзаголовок — 300 (замість поточного семи-болд для обох).
   Оверлей злегка полегшується (менше затемнення) відповідно до
   принципу "багато повітря" з брендбуку.

3. **`ProductCard`** (`src/components/storefront/ProductCard.tsx`) —
   невеликий контурний квітковий SVG-акцент у кутку картки, лише в
   новій темі, не перекриває фото товару.

### 5. Дані/потік

Немає нових колекцій чи API. Єдина нова точка даних —
`siteSettings.designTheme`, яка вже читається в `layout.tsx` (і
частково в `page.tsx`, де siteSettings теж запитується — там зміни не
потрібні, окрім передачі теми в `layout.tsx`).

`afterChange` хук глобалу `site-settings` вже робить
`revalidatePath('/')` — цього достатньо, щоб перемикання теми в
адмінці одразу відбилось на сайті (root layout ревалідується разом з
рутом).

### 6. Тестування

- Ручна перевірка в браузері (dev-сервер): увімкнути
  `designTheme = 'new'` в адмінці → перевірити головну, каталог,
  сторінку товару, кошик, чекаут, wedding, business, gift-certificates
  у новій темі; повернути на `'old'` → переконатись, що все виглядає
  так само, як зараз.
- Перевірка, що дефолтне значення поля — `'old'`, тобто без дій
  адміністратора існуючі відвідувачі нічого не побачать.
- Перевірка контрасту кольорів нової теми (текст на `--color-cream`,
  кнопки на `--color-accent`) на базовий рівень доступності (WCAG AA
  для тексту).

## Поза межами цієї ітерації (YAGNI)

- A/B-тестування чи cookie-based rollout — не потрібен, обрано простий
  глобальний тумблер.
- Перекомпонування layout сторінок (порядок секцій, нові блоки) — не
  запитувалось, лише візуальна тема + 3 названі компоненти.
- Заміна шрифту на новий вебфонт — контраст ваг Montserrat достатній,
  новий шрифт можна додати окремою ітерацією, якщо результат не
  влаштує.
- Ротація акцентних кольорів за сезоном/темою (жовтий/теракотовий/
  бордовий/рожевий із брендбуку) — сайт отримує один послідовний
  акцент (оливковий) + один другорядний (теракотовий), без
  сезонної логіки.
