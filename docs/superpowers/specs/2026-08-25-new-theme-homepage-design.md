# Новий дизайн: перекомпонування головної сторінки

Дата: 2026-08-25
Гілка: `redesign/rebrand-2026`
Залежить від: `docs/superpowers/specs/2026-08-25-rebrand-theme-toggle-design.md`
(глобальний тумблер `site-settings.designTheme`, вже реалізовано)

## Контекст

Після першої ітерації ребрендінгу (перемикач старий/новий дизайн +
кольори/лого/декоративна графіка) користувач надав референс —
скріншот бажаного вигляду головної сторінки та мобільний скріншот
конкурента (`flowerslovers.lviv.ua`) для конфігуратора підписки.
Висновок: перша ітерація змінила лише візуальну тему поверх існуючої
структури, а користувач хоче суттєво іншу композицію сторінки.

Обсяг виявився завеликим для одного проєкту й розбитий на 3 незалежні
під-проєкти (кожен — окремий цикл спека → план → реалізація):

1. **Новий макет головної сторінки** — ця спека.
2. Конфігуратор підписки (вибір розміру/частоти/дня доставки з
   динамічною ціною) — окремий проєкт, не в цій спеці.
3. Каталог з фільтрами (сайдбар + сітка товарів) — окремий проєкт, не
   в цій спеці.

## Рішення (підтверджено користувачем)

- Починаємо з **№1: головна сторінка**.
- Іконки пошуку/акаунту/вішлісту в хедері — **лише візуальні**, без
  функціоналу (буде окремою задачею пізніше).
- Hero-блок: **прибираємо підтримку відео**, лишається лише фото
  (поле `video` в Payload лишається в схемі, просто не
  використовується в новому layout).
- Новий layout головної застосовується **лише коли
  `designTheme === 'new'`**; стара версія лишається без змін.
- Секції "стрічка іконок" (доставка/ваза/пауза) та "Як це працює" —
  нові блоки, контент редагується через Payload-адмінку.
- Відгуки та Instagram-стрічка лишаються **окремими секціями**, як
  зараз — тільки візуальний рестайл під нову тему, без нових полів
  (рейтинг/кількість відгуків не додаємо).

## Архітектура

### Підхід до перемикання: `theme`-проп замість CSS-дублювання

Попередня ітерація для дрібних акцентів (`Logo`, `ProductCard`,
частково `Hero`) використовувала подвійну DOM-розмітку, перемикачувану
чистим CSS-селектором `[html[data-theme='new']_&]`. Для секцій із
**структурно іншою** розміткою (новий Hero, новий хедер, новий
FormatsGrid) цей прийом невигідний — довелося б дублювати весь JSX
двічі в одному файлі.

Замість цього — компоненти, що суттєво відрізняються між темами,
отримують проп `theme: 'old' | 'new'` і рендерять JSX умовно
(`if (theme === 'new') return <>...</> ; return <>...</>`). Це все ще
0 клієнтського JS і 0 React Context: `theme` дізнається сервер
(`page.tsx`/`layout.tsx` вже читають `site-settings.designTheme`) і
просто прокидається пропом униз, як і решта даних сторінки.

Це не скасовує CSS-підхід — він лишається для `Logo`/`ProductCard`, і
для `Hero`'s вже наявного декоративного акценту квітки (не чіпаємо).

### Компоненти

1. **`Header`** (`src/components/storefront/Header.tsx`) — новий проп
   `theme: 'old' | 'new'`. У новій темі, праворуч перед `CartDrawer`,
   рендериться ряд трьох іконок (пошук/лупа, акаунт/людина, вішліст/
   серце) — статичні `<span>` з inline SVG (в стилі контурної графіки
   бренду), без `href`, `aria-hidden` не ставимо (це кнопки-заглушки,
   тому `disabled` + `aria-label`, щоб не бити доступність порожніми
   інтерактивними елементами без дії — робимо їх `<span>` з
   `role="img"` та `aria-label`, не `<button>`, щоб не обіцяти
   функціонал, якого нема).

2. **`Hero`** (`src/components/storefront/Hero.tsx`) — новий проп
   `theme`. Стара гілка — код 1:1 як зараз (відео/фото на весь екран,
   текст по центру поверх). Нова гілка — двоколонковий `grid`:
   лівий стовпець — заголовок (вага з `--font-weight-brand-bold`),
   підзаголовок (`--font-weight-brand-light`), до двох CTA-кнопок
   (`ctaButtons` вже підтримує масив до 3 — використовуємо перші 2,
   `style: primary` → суцільна `bg-accent`, `style: secondary` →
   контурна `border-accent`); правий стовпець — `fallbackImage` у
   скругленому контейнері (`rounded-3xl`, `aspect-[4/5]` або близько
   референсу). Поле `video` в `Hero` global лишається в схемі
   (використовується старою гілкою), у новій гілці не читається.

3. **`FeatureStrip`** (новий файл
   `src/components/storefront/FeatureStrip.tsx`) — рендериться **лише
   коли `theme === 'new'`** (у старій темі секції немає взагалі,
   виклик у `page.tsx` обгортається умовою). Горизонтальний ряд 3
   пунктів `{icon, title, subtitle}` з вертикальними розділювачами між
   ними, центровано, під `Hero`.

4. **`HowItWorks`** (новий файл
   `src/components/storefront/HowItWorks.tsx`) — рендериться лише
   коли `theme === 'new'`. Заголовок + ряд пронумерованих кроків
   `{icon, title, subtitle}` (кружечок з іконкою, число не зберігаємо
   в даних — номер визначається позицією в масиві).

5. **`FormatsGrid`** (`src/components/storefront/FormatsGrid.tsx`) —
   новий проп `theme`. Дані (`FormatCardData`) не змінюються. Стара
   гілка — код 1:1 як зараз (фото на всю картку, темний градієнт,
   текст+pill-кнопка поверх). Нова гілка — фото зверху
   (`aspect-[4/3]`), білий фон картки під фото, заголовок + підзаголовок
   темним текстом, стрілка-посилання (→) замість pill-кнопки в
   правому нижньому куті картки.

6. **`TestimonialsGrid`, `InstagramFeed`** — без нового пропу
   `theme` і без структурних змін; лише токени кольору вже
   підхоплюються з CSS-змінних (як і решта сайту) — жодних правок
   коду не потрібно, крім, за потреби, дрібного вирівнювання
   відступів під новий рітм секцій (виконавець вирішує на місці, якщо
   візуально не пасує — не обов'язково).

### Нові піктограми

Без нової npm-залежності (немає icon-бібліотеки в проєкті — перевірено
`package.json`). Іконки — рукописні inline SVG в стилі контурної
графіки бренду (як `BrandFlowerAccent`), зведені в один файл
`src/components/storefront/HomeIcons.tsx`, що експортує компонент
`HomeIcon({ name, className })` з фіксованим набором `name`:
`'truck' | 'vase' | 'pause' | 'flower' | 'home' | 'sparkle'`
(6 іконок покривають і `FeatureStrip`, і `HowItWorks`; розробник може
розширити список пізніше, адмін обирає з випадаючого списку — не
завантажує довільний SVG).

```ts
        { label: 'Дім', value: 'home' },
        { label: 'Зірка', value: 'sparkle' },
      ]},
      { name: 'title', type: 'text', required: true },
      { name: 'subtitle', type: 'text' },
    ],
  },
```


The `icon` select's option list is identical in both globals — same six
values/labels as `FeatureStrip.items.icon` above.

Обидва глобали реєструються в `src/payload.config.ts`'s `globals`
масиві (поряд з `FormatsSection`), і — як і решта globals у проєкті —
мають `afterChange` хук з `revalidatePath('/', 'layout')` (той самий
патерн, що вже виправлений для `site-settings` в попередній ітерації).

`page.tsx` (`src/app/(storefront)/page.tsx`) додатково запитує ці два
globals через той самий `Promise.all`, і рендерить `<FeatureStrip>` /
`<HowItWorks>` умовно (`{theme === 'new' && <FeatureStrip .../>}`) —
щоб не ганяти зайві запити даремно, можна або завжди фетчити (дешевий
запит, простіше коду) — **обираємо завжди фетчити**, узгоджено з тим,
як уже влаштований `page.tsx` (всі globals тягнуться одним
`Promise.all` незалежно від контексту).

### Міграція БД

Два нові globals = дві нові Postgres-таблиці (`feature_strip` +
`feature_strip_items`, `how_it_works_section` +
`how_it_works_section_steps`) плюс два нові enum-типи для полів
`icon`. **Урок з попередньої ітерації: міграція для нового Payload-поля
мусить бути частиною цього ж плану, а не постфактум-виправленням.**
Виконавець генерує її через `npm run payload migrate:create
add_feature_strip_and_how_it_works` проти одноразового Postgres в
Docker (як і минулого разу), звіряє з конвенцією іменування в
`src/migrations/20260825_103829_initial_schema.ts`, і реєструє в
`src/migrations/index.ts`.

## Тестування

- `npx tsc --noEmit`, `npm run lint` — як завжди.
- Ручне QA на dev-сервері (`npm run dev`) в обох темах: головна
  сторінка — стара тема має лишитися візуально ідентичною поточному
  вигляду (Hero з відео/фото по центру, старий FormatsGrid, без
  FeatureStrip/HowItWorks); нова тема — новий Hero (2 колонки, без
  відео), FeatureStrip, новий FormatsGrid, HowItWorks, існуючі
  Testimonials/Instagram з новою палітрою.
- Перевірка адмінки: нові globals "Стрічка переваг" та "Блок 'Як це
  працює'" зʼявляються в сайдбарі групи "Контент сайту", редагування
  зберігається і одразу зʼявляється на сайті (`revalidatePath('/',
  'layout')`).

## Поза межами цієї ітерації

- Робочий пошук/акаунт/вішліст у хедері — окрема задача.
- Конфігуратор підписки та каталог з фільтрами — окремі під-проєкти
  (№2 і №3 з контексту вище).
- Обʼєднання відгуків з рейтингом/цитатою в один блок — не робимо
  (рішення користувача), лишаємо окремі секції.
- Заміна старого Hero/FormatsGrid на всьому сайті — новий layout діє
  тільки під `designTheme === 'new'`.
